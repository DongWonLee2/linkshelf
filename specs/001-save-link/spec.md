## User Scenarios & Testing *(mandatory)*

### User Story 1 - 링크 저장 (Priority: P1)

나중에 읽을 글을 발견한 사용자가 URL을 보내고, 원하면 한 줄 메모와 태그를 붙여 저장한다. 저장에 성공하면 저장된 내용(식별자, URL, 메모, 태그, 저장 시각)을 돌려받는다.

**Why this priority**: 링크를 모으는 것이 이 제품의 출발점이다. 목록 조회·태그 필터·읽음 표시(PRD-02~04)는 모두 저장된 링크가 있어야 의미가 있다.

**Independent Test**: 빈 저장소에 유효한 URL 하나를 저장 요청하고, 성공 응답과 함께 저장된 내용이 그대로 돌아오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 저장된 링크가 없음, **When** 유효한 URL만 보내 저장, **Then** 성공하고 식별자·URL·저장 시각이 돌아오며 메모는 비어 있고 태그는 빈 목록이다.
2. **Given** 저장된 링크가 없음, **When** 유효한 URL과 한글 메모·태그 2개를 보내 저장, **Then** 성공하고 메모(한글 포함)와 태그가 보낸 그대로 돌아온다.
3. **Given** 저장된 링크가 없음, **When** 500자 메모, 30자 태그 10개로 저장, **Then** 성공한다.

---

### User Story 2 - 잘못된 입력 거부 (Priority: P1)

사용자가 URL을 빠뜨리거나 형식이 틀린 값을 보내거나 메모·태그가 한도를 넘으면 저장되지 않고, 어느 항목이 왜 거부됐는지 알려 준다.

**Why this priority**: 잘못된 데이터가 쌓이면 이후 목록·필터 기능이 모두 오염된다. 저장과 함께 처음부터 있어야 한다.

**Independent Test**: 형식이 틀린 URL로 저장을 요청해 거부되고 아무것도 저장되지 않았는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 아무 상태, **When** URL 없이(또는 빈 문자열로) 저장, **Then** 입력 오류로 거부되고 URL 항목이 오류로 표시된다.
2. **Given** 아무 상태, **When** `not a url`, `ftp://example.com`, `http://`처럼 허용되지 않는 URL로 저장, **Then** 입력 오류로 거부되고 URL 항목이 오류로 표시된다.
3. **Given** 아무 상태, **When** 501자 메모로 저장, **Then** 입력 오류로 거부되고 메모 항목이 오류로 표시된다.
4. **Given** 아무 상태, **When** 태그 11개 또는 31자 태그로 저장, **Then** 입력 오류로 거부되고 태그 항목이 오류로 표시된다.
5. **Given** 위 어느 거부 사례든, **When** 거부된 뒤, **Then** 저장된 링크 수는 변하지 않는다.

---

### User Story 3 - 중복 URL 거부 (Priority: P2)

같은 링크를 두 번 저장하려 하면 이미 저장돼 있다고 알려 주고 새로 저장하지 않는다.

**Why this priority**: 중복은 데이터를 해치지는 않지만 목록을 지저분하게 만든다. 입력 형식 검증보다 우선순위가 낮다.

**Independent Test**: 같은 URL로 두 번 저장을 요청해, 두 번째 요청이 중복으로 거부되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** `https://example.com/a`가 저장돼 있음, **When** 같은 URL을 다시 저장, **Then** 중복으로 거부되고 저장된 링크 수는 1로 유지된다.
2. **Given** `https://example.com/a`가 저장돼 있음, **When** `HTTPS://Example.COM:443/a`를 저장, **Then** 중복으로 거부된다.
3. **Given** `https://example.com/a`가 저장돼 있음, **When** `https://example.com/a/`를 저장, **Then** 다른 URL로 보고 성공한다.
4. **Given** `https://example.com/a`가 저장돼 있음, **When** `https://example.com/b`를 저장, **Then** 성공한다.

---

### Edge Cases

- URL 앞뒤 공백: 앞뒤 공백을 제거한 뒤 검증·저장한다.
- 메모가 공백만 있는 경우: 메모 없음과 같게 취급한다.
- 길이 계산(URL·메모·태그 공통): 유니코드 코드 포인트 수로 센다. 한글 1자, 😀 1자, 피부색이 붙은 👍🏽는 2자다.
- 태그 중복: 같은 요청 안에서 공백 제거 후 대소문자만 다르거나 같은 태그가 여러 번 오면 하나로 합치고, 처음 나온 표기를 남긴다. 예: `["Java", " java ", "JAVA"]` → `["Java"]`.
- 빈 태그(공백만 있는 태그): 입력 오류로 거부한다.
- 매우 긴 URL: 2,048자를 넘으면 입력 오류로 거부한다.
- 한글 도메인(`https://한국.kr/a`): 호스트를 읽을 수 없는 URL로 보고 입력 오류로 거부한다. punycode 형태(`https://xn--3e0b707e.kr/a`)는 허용한다.
- 같은 URL을 거의 동시에 두 번 저장: 하나만 저장되고 다른 하나는 중복으로 거부된다.
- 여러 항목이 동시에 틀린 경우: 틀린 항목을 모두 한 번에 알려 준다.

## Requirements *(mandatory)*

각 요구사항은 `R-LINK-NN (출처 PRD 번호)` 형식으로 적는다.

### Functional Requirements

- **R-LINK-01** (PRD-01): 사용자는 URL과 선택적 메모·태그로 링크를 저장할 수 있다. 성공하면 시스템은 식별자, 저장된 URL, 메모, 태그 목록, 저장 시각을 돌려준다.
- **R-LINK-02** (PRD-01): URL은 필수이며, 스킴이 `http` 또는 `https`이고 호스트가 있는 절대 URL이어야 하고, 앞뒤 공백 제거 후 2,048자 이하여야 한다. 아니면 입력 오류로 거부하고 URL 항목을 오류로 표시한다.
- **R-LINK-03** (PRD-01): 메모는 선택이며 최대 500자다(500자는 허용, 501자는 거부). 넘으면 입력 오류로 거부하고 메모 항목을 오류로 표시한다.
- **R-LINK-04** (PRD-01): 이미 저장된 URL과 같은 URL은 중복으로 거부한다. 같은 URL 판정과 저장은 다음 정규화 후의 형태로 한다: 앞뒤 공백 제거, 스킴·호스트 소문자화, 기본 포트(`http`의 80, `https`의 443) 제거. 경로·쿼리·프래그먼트(`#…`)와 경로 끝 슬래시는 바꾸지 않는다. 예: `HTTPS://Example.com:443/a`는 `https://example.com/a`와 같고, `https://example.com/a/`·`https://example.com/A`·`https://example.com/a#x`는 서로 다르다.
- **R-LINK-05** (PRD-01): 태그는 선택이며 링크당 최대 10개(중복 합친 뒤 기준), 태그 하나는 앞뒤 공백 제거 후 최대 30자다. 남긴 태그의 대소문자는 보낸 그대로 저장한다. 태그 순서는 처음 나온 순서를 따른다. 각 태그는 앞뒤 공백을 제거하고, 빈 태그는 거부하며, 같은 요청 안에서 대소문자를 무시했을 때 같은 태그는 하나로 합치고 처음 나온 표기를 남긴다. 한도를 넘으면 입력 오류로 거부하고 태그 항목을 오류로 표시한다.
- **R-LINK-06** (PRD-01): 입력 오류든 중복이든 거부된 요청은 아무것도 저장하지 않는다. 거부 응답은 입력 오류와 중복을 서로 구분할 수 있어야 하고, 입력 오류일 때는 틀린 항목과 이유를 모두 담는다.
- **R-LINK-07** (PRD-01, PRD §6): 한글을 포함한 메모와 태그는 저장된 뒤 보낸 그대로 돌아와야 한다(글자 깨짐 없음).
- **R-LINK-08** (PRD-01): URL·메모·태그의 길이 한도는 모두 유니코드 코드 포인트 수로 센다.

### Key Entities *(include if feature involves data)*

- **링크(Link)**: 사용자가 저장한 읽을거리 하나. 속성: 식별자, URL(저장된 형태), 메모(선택), 태그 목록(0개 이상), 저장 시각. URL은 시스템 전체에서 유일하다.
- **태그(Tag)**: 링크에 붙는 짧은 분류 이름. 이번 기능에서는 링크에 딸린 문자열 목록으로만 다루며, 태그 자체를 관리하는 기능은 없다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 유효한 저장 요청은 100% 성공하고, 돌려받은 내용이 보낸 URL·메모·태그와 일치한다(한글 포함).
- **SC-002**: R-LINK-02~05의 거부 사례(URL 누락·형식 오류·길이 초과, 메모 초과, 태그 초과, 중복)가 모두 자동 테스트로 검증되고, 각 사례에서 저장된 링크 수가 변하지 않는다.
- **SC-003**: 한도 경계값(메모 500/501자, 태그 10/11개, 태그 30/31자)이 자동 테스트로 검증된다. 메모 경계는 한글과 이모지를 섞은 입력으로도 검증한다.
- **SC-004**: 요구사항 R-LINK-01~08이 각각 최소 하나의 테스트 이름과 연결된다.

## Assumptions

- 사용자는 1명이며 로그인·권한 확인은 없다(PRD §2, §4).
- 링크 제목·미리보기를 가져오려고 외부로 요청을 보내지 않는다. URL이 실제로 열리는지 확인하지 않는다(PRD §4, §6).
- 이번 기능은 저장만 다룬다. 목록 조회(PRD-02), 태그 필터(PRD-03), 읽음 표시(PRD-04), 수정·삭제는 범위 밖이다.
- 화면 없이 백엔드 API만 제공한다(프론트엔드는 MVP-3).
- 허용 스킴은 `http`/`https`만이며, URL 최대 길이 2,048자는 흔히 쓰는 상한을 따른 기본값이다.
- 응답 형식·오류 형식·상태 코드 같은 구체 계약은 ADR-0001을 따라 plan 단계에서 정한다.
