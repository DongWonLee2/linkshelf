## User Scenarios & Testing *(mandatory)*

### User Story 1 - 안 읽은 링크만 받기 (Priority: P1)

사용자가 링크 목록을 안 읽은 것만 받는다. 고르지 않으면 지금처럼 전부 받는다. 태그 거르기, 정렬, 쪽 나누기와 함께 쓸 수 있다.

**Why this priority**: 거르는 동작이 있어야 이 기능이 의미가 있다. 화면(US2)도 이 동작에 기댄다.

**Independent Test**: 링크 3개를 저장하고 하나를 읽음으로 지정한 뒤, 안 읽은 것만 요청해 나머지 2개만 돌아오는지, 지정하지 않은 요청은 3개 그대로인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 링크 A, B, C를 이 순서로 저장하고 B를 읽음으로 지정함, **When** 안 읽은 것만 요청, **Then** C, A 순서로 돌아오고 전체 개수는 2다.
2. **Given** 위와 같음, **When** 안 읽음 조건을 지정하지 않거나 "끔"으로 요청, **Then** C, B, A가 돌아오고 응답이 이 기능 전과 같다.
3. **Given** 위와 같음, **When** 안 읽은 것만 오래된순으로 요청, **Then** A, C 순서로 돌아온다.
4. **Given** A(태그 `java`, 안 읽음), B(태그 `java`, 읽음), C(태그 없음, 안 읽음), **When** 태그 `java`로 거르고 안 읽은 것만 요청, **Then** A만 돌아오고 전체 개수는 1이다.
5. **Given** 한 쪽 크기보다 많은 안 읽은 링크가 있음, **When** 안 읽은 것만 모든 쪽을 차례로 요청, **Then** 안 읽은 링크가 빠짐없이, 겹침 없이 나뉘어 돌아온다.
6. **Given** 아무 상태, **When** 안 읽음 조건에 정해진 두 값(켬·끔) 말고 다른 값(빈 값, 대소문자가 다른 값, `yes`·`on`·`1` 같은 다른 참 표기 포함)으로 요청, **Then** 입력 오류로 거부되고 오류는 틀린 항목이 안 읽음 조건임을 알려 준다.
7. **Given** 모든 링크가 읽음, **When** 안 읽은 것만 요청, **Then** 빈 목록(전체 개수 0)으로 성공한다.

### User Story 2 - 화면에서 안 읽은 것만 보기 (Priority: P2)

사용자가 정렬 선택 상자 옆의 "안 읽은 것만" 체크박스를 켠다. 목록이 첫 쪽부터 안 읽은 링크만 보인다. 끄면 다시 전부 보인다.

**Why this priority**: 사용자는 화면으로 기능을 쓴다. API(US1)가 먼저 있어야 한다.

**Independent Test**: 읽음·안 읽음이 섞인 화면에서 체크박스를 켜 읽음 항목이 사라지고 쪽 정보가 첫 쪽인지, 끄면 읽음 항목이 다시 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 화면을 처음 열었음, **When** 체크박스를 확인, **Then** 꺼져 있고 목록은 읽음·안 읽음을 모두 보인다.
2. **Given** 링크가 여러 쪽에 걸쳐 있고 사용자가 2쪽에 있음, **When** 체크박스를 켬, **Then** 목록이 첫 쪽부터 안 읽은 링크만 보인다.
3. **Given** 태그 필터를 적용하고 오래된순으로 보고 있음, **When** 체크박스를 켜거나 끔, **Then** 태그 필터와 정렬은 그대로이고 결과가 첫 쪽부터 보인다.
4. **Given** 체크박스를 켠 상태, **When** 쪽을 넘기거나, 태그 필터를 적용·해제하거나, 정렬을 바꿈, **Then** 체크박스는 켜진 채이고 결과도 안 읽은 것만이다.
5. **Given** 체크박스를 켠 상태, **When** 화면을 새로 고침, **Then** 체크박스는 꺼지고 전부 보인다.
6. **Given** 체크박스를 켠 상태, **When** 링크를 새로 저장함, **Then** 체크박스가 꺼지고, 목록이 필터 없이 첫 쪽부터 최신순으로 보여 새 링크가 맨 위에 있다.
7. **Given** 체크박스를 켠 상태, **When** 목록의 한 항목을 읽음으로 바꿈, **Then** 그 항목은 목록에 남고 체크 상태만 읽음으로 바뀐다. 다시 불러오면(체크박스를 껐다 켜거나 첫 쪽으로 다시 불러옴) 빠진다.

### User Story 3 - 겹친 조작에도 고른 조건대로 보기 (Priority: P3)

사용자가 앞 조작의 응답을 기다리지 않고 다음 조건을 바꾼다. 화면은 사용자가 마지막으로 고른 태그·정렬·안 읽음 조건을 모두 반영한 목록을 보인다.

**Why this priority**: 같은 종류의 경쟁 결함(정렬 기능의 필터 경쟁)이 리뷰에서 흔들리며 잡혔다. 테스트로 먼저 고정한다. 기능 자체는 US1·US2로 쓸 수 있다.

**Independent Test**: 목록 응답을 늦춘 상태에서 태그 적용 직후 체크박스를 켜, 마지막 요청이 태그와 안 읽음 조건을 모두 담고 화면이 그 결과인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 태그 적용(또는 해제) 요청이 아직 진행 중, **When** 체크박스를 켬, **Then** 새 요청은 방금 적용(해제)한 태그와 안 읽음 켬을 함께 담고, 화면은 그 결과와 그 태그 필터 표시를 보인다.
2. **Given** 체크박스 켜기 요청이 아직 진행 중, **When** 정렬을 바꿈, **Then** 새 요청은 안 읽음 켬과 새 정렬을 함께 담고, 화면의 체크박스는 켜진 채다.
3. **Given** 체크박스를 켠 상태에서 링크를 저장해 다시 불러오기가 아직 진행 중, **When** 체크박스를 다시 켬, **Then** 새 요청은 필터 해제(태그 없음)·최신순·안 읽음 켬을 담고, 화면은 그 결과를 보인다.

---

### Edge Cases

- **쪽 밀림(기록만, 막지 않음)**: 체크박스를 켠 채 1쪽의 항목 k개를 읽음으로 바꾼 뒤 다음 쪽으로 가면, 서버에서는 그 k개가 빠져 원래 2쪽 앞부분 k개가 1쪽으로 당겨진다. 그래서 그 k개는 1쪽에도 2쪽에도 보이지 않는다. 앞 쪽으로 돌아가거나 체크박스를 껐다 켜면 보인다. 밀림 때문에 넘어간 쪽이 비면 R-UI-03대로 빈 목록 안내만 보이고 쪽 넘김은 숨겨진다. 이때 빠져나오는 길은 체크박스를 껐다 켜거나 링크를 저장하는 것이다(clarify A). 이 동작은 테스트 하나로 고정한다(사용자 결정: "이번에는 막지 않고 기록만 한다").
- 체크박스를 켜거나 끄는 중 목록 불러오기가 실패: 실패 안내(`list-error`)를 보인다(R-UI-03). 체크박스는 사용자가 고른 값을 유지한다. 다시 누르면 반대 값으로 다시 불러온다.
- 거른 결과가 없음: 기존 빈 목록 안내(`link-list-empty`)를 같은 문구로 보인다. 쪽 정보는 보이지 않는다(R-UI-03 기존 규칙).
- 안 읽음 조건과 쪽 번호·쪽 크기·태그·정렬이 함께 틀림: 틀린 항목을 모두 알려 준다. 숫자가 아닌 쪽 번호·크기가 있으면 R-LINK-11 예외(그 항목만 알림)를 따른다.
- 안 읽음 조건을 두 번 보냄: 입력 오류(정렬·태그와 같은 규칙).
- **범위 밖, #46에서 함께 고친다**: 태그 적용 요청이 입력 오류(400)로 끝나는 동안 체크박스를 누르는 경우. 정렬 변경의 같은 결함(#46)과 원인이 같다.

## Requirements *(mandatory)*

백엔드는 spec 004의 R-LINK-21에 이어 `R-LINK-NN (출처)`, 화면은 spec 004의 R-UI-20에 이어 `R-UI-NN (출처)`로 적는다. 화면 요소 이름은 `.claude/skills/verify-linkshelf/features/README.md` 표의 `data-testid`와 같다. 새 testid는 같은 PR에서 표에 먼저 넣는다.

### Functional Requirements

- **R-LINK-22** (PRD-06): 사용자는 목록을 안 읽은 링크만으로 거를 수 있다. 조건을 생략하거나 "끔"이면 거르지 않고 응답은 이 기능 전과 같다.
- **R-LINK-23** (PRD-06): 안 읽음 거르기는 태그 거르기(R-LINK-12), 정렬(R-LINK-19), 쪽 나누기(R-LINK-10)와 함께 동작한다. 두 조건으로 거른 결과를 고른 순서로 정렬한 뒤 나눈다. 전체 개수와 전체 쪽 수는 거른 결과만 센다.
- **R-LINK-24** (PRD-06): 안 읽음 조건은 정해진 두 값과 정확히 같을 때만 받는다. 빈 값, 대소문자·앞뒤 공백이 다른 값, 다른 참·거짓 표기(`yes`, `on`, `1` 등), 두 번 보낸 값은 입력 오류로 거부하고, 기존 오류 형식으로 틀린 항목이 안 읽음 조건임을 알려 준다. 다른 항목 오류와 함께 있으면 R-LINK-11대로 모두 알려 준다. 값을 고쳐서 처리하지 않는다.
- **R-UI-21** (PRD-06): 정렬 선택 상자 옆에 "안 읽은 것만" 체크박스(`link-unread-only-toggle`)를 둔다. 화면을 열거나 새로 고치면 꺼져 있다. 상태는 주소에 남기지 않는다. 불러오는 중에도 비활성으로 만들지 않는다(비활성 컨트롤은 포커스를 잃는다).
- **R-UI-22** (PRD-06): 체크박스를 켜거나 끄면 현재 태그 필터와 정렬을 유지한 채 첫 쪽부터 다시 불러온다. 쪽 넘김, 태그 필터 적용·해제, 정렬 변경은 현재 안 읽음 상태를 유지한다. 체크박스로 첫 쪽에 돌아갈 때는 R-UI-16·17의 스크롤·포커스 이동을 하지 않는다.
- **R-UI-23** (PRD-06): 링크 저장에 성공하면(R-UI-05·20) 체크박스를 끈다. 다시 불러오는 목록도 안 읽음으로 거르지 않는다.
- **R-UI-24** (PRD-06): 목록 요청이 진행 중일 때 체크박스, 태그 필터 적용·해제, 정렬, 저장 뒤 다시 불러오기 중 하나가 새 요청을 만들면, 새 요청은 사용자가 마지막으로 고른 태그·정렬·안 읽음 값을 모두 담는다(직전에 화면에 보인 값이 아니다). 화면의 체크박스·정렬·필터 표시는 마지막 요청의 값과 같다. 목록 요청이 실패해도 마지막으로 고른 정렬·안 읽음 값은 되돌리지 않는다(선택 상자·체크박스는 고른 값 그대로, 다음 요청도 그 값을 쓴다). 태그는 성공해야 적용되므로(R-UI-07·08) 실패하면 화면에 적용된 필터로 돌아간다. 태그 적용이 입력 오류로 끝나는 경우는 범위 밖이다(#46).
- **R-UI-25** (PRD-06): 체크박스를 켠 상태에서 항목을 읽음으로 바꿔도 그 항목은 목록에 남고, R-UI-09·10(먼저 바꾸고 실패하면 되돌림)이 그대로 적용된다. 다시 불러올 때 빠진다. 이때 생기는 쪽 밀림(Edge Cases)은 막지 않는다.

### Key Entities *(include if feature involves data)*

- **안 읽음 조건**: 켬 또는 끔. 저장하지 않는 요청 조건이다. 링크 데이터와 DB 스키마는 바뀌지 않는다(읽음 여부는 spec 002 R-LINK-15~18의 기존 값을 쓴다).
- **화면 상태**: spec 003·004의 화면 상태(현재 쪽, 필터 태그, 정렬, 폼)에 안 읽음 조건을 더한다. 새로 고치면 꺼짐으로 돌아간다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 화면에서 한 번 눌러 안 읽은 링크만 볼 수 있다(E2E 하나가 같은 흐름을 통과).
- **SC-002**: 안 읽음 조건을 지정하지 않은 기존 요청과 기존 자동 테스트(백엔드·E2E)가 모두 이 기능 전과 같은 결과로 통과한다.
- **SC-003**: 고장 내기 네 가지가 각각 해당 테스트를 실패시킨다(quickstart §5와 같음). (1) 거르기 조건을 뒤집어 읽은 것만 오게 하면 R-LINK-22·23 테스트가 실패한다. (2) 컨트롤러가 `unread`를 `Boolean`으로 받으면 R-LINK-24 `yes`·`on`·`1` 테스트가 실패한다. (3) 새 요청이 "마지막으로 고른 값" 대신 "직전에 성공한 값"을 쓰게 하면 R-UI-24 경쟁 테스트 3개가 모두 실패한다. (4) 저장 뒤 안 읽음을 끄지 않으면 R-UI-23 테스트가 실패한다.
- **SC-004**: 각 R-ID가 최소 하나의 자동 테스트와 연결되고, verify-linkshelf `unread-filter` 여정 한 바퀴가 실제 앱에서 PASS한다.

## Assumptions

- 사용자는 1명, 로그인 없음, 로컬 실행(PRD §6). 링크 수는 수천 개 이하라 성능 목표를 따로 두지 않는다.
- 범위 밖: "읽은 것만 보기", 세 상태(전체/안 읽음/읽음), 읽음 지정 즉시 목록에서 빼기, 쪽 밀림 막기, 상태를 주소나 저장소에 남기기, 태그 400 진행 중 토글(#46).
- 파라미터 이름과 값은 grilling Q7 결정(`unread=true|false`, 생략 = `false`), 오류 메시지는 grilling Q8 결정(`true 또는 false여야 합니다`)을 plan에서 계약 문서로 옮기고 승인받는다.
- 체크박스가 들어가면 Visual QA 기준 이미지(R-UI-13)가 바뀐다. 기준 이미지는 같은 PR에서 자동 검사 환경으로 다시 만든다.
- 결정 기록: 거르기 조건은 `adr/tech-decision-checklist.md`대로 이 spec에 둔다. ADR은 만들지 않는다(grilling Q6).
- 로컬 `docs/prd.md`의 PRD-06 줄은 구현 흐름이 정해진 뒤 메인 체크아웃에서 넣는다(로컬 전용).
