## 1. 해결하려는 문제

나중에 읽으려고 모아 둔 링크가 브라우저 탭·메신저·메모 앱에 흩어지고 잊힌다.
(가설: 한곳에 모으고 태그로 거르고 읽음 표시를 하면 다시 찾고 읽게 된다. 검증되지 않음.)

## 2. 대상 사용자와 JTBD

- 주 사용자: 이 저장소 소유자 1명 (로컬에서 혼자 사용)
- 주요 상황: 읽을거리를 발견했을 때 URL·한 줄 메모·태그를 남기고, 나중에 태그로 골라 읽는다.
- 제외: 여러 사용자, 팀 공유, 모바일 앱

## 6. 비기능 요구·제약

- 사용성: 한글 메모 입력·저장·조회가 깨지지 않는다(UTF-8).
- 보안/개인정보: 로컬 전용, 인증 없음. 외부로 요청을 보내지 않는다.
- 규모: 1인, 수천 건 이하. 성능 목표 없음.
- 실행: 로컬에서 실행. 테스트는 자동화하고 CI에서 돈다.
- 비용: 무료 도구만(GitHub public 저장소의 Actions).

## 7. 핵심 가설 및 미확인 사항

- 가설: 이 프로젝트의 주목적은 AI 개발 흐름(PRD → Spec → Issue → TDD → PR) 검증이며, 제품 가치 검증은 범위 밖이다.
- 미확인: 메모 최대 길이, URL 정규화 범위, 태그 개수 제한 → 5단계 `/speckit-clarify`에서 결정.
